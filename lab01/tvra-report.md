| **ID** | **Threat event** | **Threat source** | **Vulnerability / predisposing condition** | **Likeli-hood** | **Impact** | **Risk** | **Recommended mitigation** |
|----|----|----|----|----|----|----|----|
| R-01 | Adversary sends arbitrary traffic through the perimeter to any internal host | Adversarial — external attacker with moderate capability | The edge router nftables ruleset sets the input, forward and output chains to policy accept. Only NAT is configured; no packet filtering is enforced at the perimeter. | **Very High** | **Very High** | **Very High** | Change the forward and input chain policies to drop and add explicit accept rules for permitted flows only: HTTP to the reverse proxy host, established and related connections, and management access from the administration workstation. Verify with a port scan from the external segment. |
| R-02 | Adversary completes an exposed application installer and gains administrative control of a public website | Adversarial — external attacker, opportunistic | Both internet-facing applications are reachable at their installation wizards. Any external user can set the site name, administrator credentials and database connection. | **Very High** | **Very High** | **Very High** | Complete both installations immediately, then remove or rename the installation directories. Restrict installer paths at the reverse proxy until setup is finished. Re-test from the external segment to confirm the installers no longer respond. |
| R-03 | Adversary uses the exposed database manager to create, drop or dump application databases | Adversarial — external or internal attacker | The collaboration platform presents an unprotected database manager and displays a generated master password in the page body. | **High** | **Very High** | **Very High** | Set a strong master password in the application configuration, disable the database manager in production configuration, and restrict the management path at the proxy to the administration workstation address. |
| R-04 | Adversary moves laterally from a compromised public web host to internal services | Adversarial — external attacker | All services share a single flat segment with no east-west filtering. A host serving untrusted traffic sits in the same broadcast domain as the file server and domain controller. | **High** | **Very High** | **Very High** | Separate public-facing services, internal services and infrastructure into distinct segments with filtering between them. As an interim control, apply host firewall rules on the domain controller and file server that permit only required source addresses. |
| R-05 | Adversary obtains domain credentials or directory access from a compromised internal host | Adversarial — external attacker with elevated capability | The domain controller is directly reachable from every host on the flat segment, including the container host serving untrusted traffic. | **Moderate** | **Very High** | **High** | Restrict directory and authentication ports to hosts that require them. Keep internet-facing hosts out of the domain, as already implemented. Enable directory service auditing and review authentication events. |
| R-06 | Adversary intercepts or modifies traffic between internal hosts using ARP cache poisoning | Adversarial — attacker with a foothold on the internal segment | A single broadcast domain with no layer 2 protections such as dynamic ARP inspection or port security. | **High** | **High** | **High** | Segment the network to reduce the size of the broadcast domain. Enforce SMB signing and encryption, already applied on the file server, and extend TLS to the web applications so intercepted traffic remains unusable. |
| R-07 | Adversary introduces a rogue DHCP server and redirects clients to attacker-controlled resolvers or gateways | Adversarial — attacker with a foothold on the internal segment | No DHCP snooping or port security. Any host on the flat segment can answer broadcast discovery before the legitimate server. | **Moderate** | **High** | **High** | Enable DHCP snooping on managed switching where available. Monitor for unexpected offers using periodic discovery scans. Configure critical infrastructure statically so it cannot be redirected by a rogue lease. |
| R-08 | Address conflict causes loss of availability for infrastructure services | Structural — configuration error; also exploitable adversarially | The DHCP dynamic pool overlaps addresses assigned statically to infrastructure hosts. A lease for an address already in use by a service was observed in the lease database. | **High** | **High** | **High** | Narrow the dynamic pool so it excludes every static address and reservation. Restart the service and confirm the lease database contains no addresses within the infrastructure range. |
| R-09 | Compromise of one service yields control of an unrelated security function | Adversarial — external attacker | File sharing and address assignment are hosted on the same system, so a single compromise yields both stored data and control of network configuration distributed to clients. | **Moderate** | **High** | **High** | Separate the roles onto distinct hosts. Where consolidation is unavoidable, restrict administrative access, enable service-level auditing, and monitor for unexpected changes to the scope configuration. |
